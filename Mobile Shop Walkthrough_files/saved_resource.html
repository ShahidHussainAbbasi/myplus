Mobile Shop — test it step by step

Six requirements, in the order a real shop would meet them: set the business up, mark a handset as serial-tracked, receive stock with IMEIs, and sell one. Each step says what to expect, and what should be refused — a refusal is a result too.

Worth knowing before step 1

A mobile shop is retail plus serial tracking — it is not its own business type. That is why step 1 exists: the Retail profile deliberately does not switch IMEI tracking on, because a furniture showroom is also retail and has no IMEIs. You turn it on yourself, and that is a one-time act.

Set the shop up

1

Tell the system what kind of shop this is

Log in as owner.mobile@myplus.com.

  1. Sidebar → Settings → Configuration.
  2. Find “What kind of business this is” → set Type of business to Retail counter / POS.
  3. Find “What this business does” → switch ON:
    • Track individual serial / IMEI numbers
    • Record item condition (new / used)
Expect

Each switch saves on the spot. Nothing else on the screen changes yet — the switches decide what the shop may do; the next steps decide which products actually use it.

2

Mark a handset as serial-tracked

A shop sells handsets that need an IMEI and chargers that never will. This is set per product, not for the whole shop.

  1. Sidebar → Register → Product.
  2. Add a product — e.g. name Redmi Note 13, a selling price, unit pcs.
  3. On the Tracking row, tick “Needs a serial / IMEI”.
  4. Save. Then add a second product — e.g. USB-C Charger — and leave Tracking unticked.
Expect

Both save normally. The Tracking row is only visible because you switched the capability on in step 1 — that is the two-level rule working.

Receive stock

3

Buy three handsets, with their IMEIs

  1. Sidebar → Purchase.
  2. Choose Redmi Note 13, quantity 3, fill in the rates.
  3. In Serial / IMEI, enter three numbers — one per line: 111111111111111, 222222222222222, 333333333333333.
  4. Set Condition to New. Save.
Expect

The purchase saves. Three individual units are now on the shelf — not just “quantity 3”.

4

Now try to get it wrong — on purpose

These are the checks that make the register trustworthy. Each should be refused before anything is saved.

  1. Too few IMEIs: quantity 3, but enter only two numbers. Save.
  2. A duplicate: quantity 1, IMEI 111111111111111 — one you already received. Save.
  3. None at all: quantity 1, leave Serial / IMEI empty. Save.
Expect refusals

1 — “This purchase is for 3 unit(s) but 2 serial number(s) were entered.”
2 — “Serial "111111111111111" is already in stock.”
3 — “This product is tracked by serial number, so each unit received needs one.”

Also check

Buy the USB-C Charger, quantity 10, with no serials at all. It saves normally — a product that needs no IMEI is completely unaffected.

Sell one

5

Sell a handset by its IMEI

  1. Sidebar → Sell → Sale.
  2. Pick Redmi Note 13, quantity 1.
  3. In Serial / IMEI, type 111111111111111 and tab out.
  4. Add to cart, then complete the sale.
Expect

As you leave the field, a small badge appears under it: New — the condition recorded when that unit was received. The sale then completes normally.

Then try to sell it twice

Start another sale with the same IMEI. It is refused: “Serial "111111111111111" is not in stock.” One physical handset cannot be sold to two customers.

6

A used handset says so, before the money is taken

The grade is recorded at intake. It has to be visible at the counter, not in a report afterwards.

  1. Go to Purchase, receive one more Redmi Note 13 — IMEI 444444444444444, Condition: Used. Save.
  2. Go to Sell → Sale, pick the product, and type 444444444444444.
  3. Then clear it and type something that was never received, e.g. 999999999999999.
Expect three different badges

New for a new unit  ·  Used in amber, because it changes what the customer is buying  ·  Not in stock in red for an unknown IMEI.

7

Ask the register where a handset went

This is the question the whole feature exists for — a warranty claim, a return, or a police enquiry all start here.

  1. While still logged in, open this in the same browser:
    http://localhost:8080/serialHistory?serial=111111111111111
Expect

JSON showing that unit: status: "SOLD", the invoiceNo it left on, and the purchaseId that brought it in. Before this feature existed, an IMEI was only ever recorded when a handset was sold on instalments — a cash sale recorded nothing.

Known gap

There is no screen for browsing the register yet — only this address. Worth deciding whether you want one (a “find a handset” search on the dashboard) as a follow-up.

The checks that prove it is per-shop, not global

8

A POS shop sees none of this

Same software, same screens, different business. If a hardware counter is asked for an IMEI, the design has failed.

  1. Log out. Log in as owner.business@myplus.com.
  2. Open Purchase, then Sell → Sale.
Expect

No Serial / IMEI field and no Condition selector on either screen. Open Register → Product and the Tracking row is gone too — a shop without the capability cannot even mark a product as serial-tracked.

9

Owner, admin and user see different things

  1. Log in as each of the three *.mobile@myplus.com accounts in turn.
  2. Each time, check the sidebar for Finance and for Settings → Configuration.

The other two requirements

10

Grids show 50 rows, and the phone layout fits

  1. Open Register → Product. Check the rows-per-page selector.
  2. Open the Sale screen on an actual phone, or in the browser’s device mode at 360 × 800 (Infinix Hot 40 / Vivo Y400 both report 360).
Expect

Grids open on 50 rows, with 10 / 25 / 50 / 100 / Show all available.
On the 360-wide sale screen, every field sits fully on screen — nothing clipped at the left edge, and no sideways scrolling.

What is not covered

Stated plainly so you are not surprised while testing:

  • No register browse screen. Serial history is reachable only by the address in step 7.
  • Condition is per delivery, not per unit. A mixed intake — three new, two used, one price — is entered as two purchase lines.
  • A sale return does not yet put the unit back on the shelf. The mechanism exists in the database; it is not wired to the returns screen.
  • The condition does not print on the receipt. It is shown at the till only.
